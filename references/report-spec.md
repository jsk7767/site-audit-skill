# 보고서 구조와 QA 기준

기존 `Desktop\데이터` 의 SEO 진단서 10편 + 디자인 감사서 12편에서 정착된 구조를 그대로 쓴다. 독자는 매장 대표다. 설명보다 판정, 판정보다 근거.

## 섹션 순서 (report.html)

1. **머리말** — 제목(매장명 + 사이트 진단), 2~3문장 결론, 메타(대상·진단일·범위·모드·도구)
2. **점수카드** — SEO(7범주 막대) · GEO(6범주 막대) · 디자인(판정 + 검출/조치/검토/렌더 결함). 아래 한 줄: 점수는 순위 예측이 아님 + 자가진단 8/15 자동
3. **세 지렛대** — 상승폭 큰 3개. 제목은 현상("canonical 도 OG 도 없습니다"), 본문은 왜·무엇을, 하단에 예상 상승·작업량
4. **SEO — NN점** — 범주별: FAIL/HOLD 카드(칩·제목·설명·근거·조치·참조), 양호 항목은 접힘
5. **GEO · AEO — NN점** — 같은 형식. NEO(네이버) 범주 포함
6. **디자인 — 판정** — 룰별 카드(건수·조치/검토/정당/참고/오탐 내역·CSS/마크업 유래·언어판별·예시), 렌더 실측 카드
7. **첫 화면(접힘 위)** — 모바일·데스크톱 스크린샷 (사람이 볼 것)
8. **룰셋 밖의 판단** — narrative.judgment. 없으면 빨간 경고 → QA FAIL
9. **실행 계획** — P0/P1/P2 표 (narrative.plan 우선, 없으면 findings 자동)
10. **점수 시뮬레이션** — 현재 → P0 → P1 → P2 (SEO/GEO)
11. **N개 사이트 비교** — `--compare` 있을 때
12. **확인한 범위와 확인하지 못한 것** — 두 열. HOLD 항목이 오른쪽에 자동 포함
13. **바닥글** — 도구·가중치 출처·시점 의존 고지

**보고서에 싣지 않는 것 (2026-09-03 사용자 결정)**: 『필살기 100』·가이드북·워크북 등 외부 자료 참조 표기(K##·G-*·NEO-* 코드, 책 제목·저자·출판사)와 자가진단표 채점. 이 코드는 `findings.json.refs` 와 스킬 내부 문서(`checklist-map.md`)에만 둔다. 고객이 보는 화면에는 판정·근거·조치만.

## 문장 규칙

- 제목은 현상을 말한다: "OG 태그가 7페이지 전부 없습니다" (○) / "OG 태그 점검" (×)
- 숫자는 근거 블록에. 본문 문장에는 한두 개만.
- 한국어 본문에 긴 줄표(—) 금지. 쉼표·가운뎃점·문장 분리. (anti-slop 이 이 보고서도 검사한다)
- "확인했다" 는 재현 가능한 근거가 있을 때만. 샘플이면 샘플이라고.
- 기계 판정 ↔ 사람 판단 분리. 판단 절 첫 문장은 "탐지기 결과가 아니라 의견".

## QA (site_qa.py) — 전부 PASS 여야 완료

| 검사 | 기준 |
|---|---|
| 데스크톱 1000px 라이트/다크 · 모바일 390px | body 가로 넘침 0 (scrollWidth == clientWidth) |
| 콘솔 | 오류 0 |
| 구조 | section ≥ 8, `.finding` ≥ 1, 깨진 이미지 0 |
| 판단 | `.judg .warn` 없음 (narrative.json judgment 작성) |
| 보안 | `C:\Users`, `SRV_PW`, `password`, `Bearer ` 문자열 0 |
| PDF(`--pdf`) | thejsk `export_pdf.py` 로 A4 생성, 빈 페이지 0 |

추가로 완료 전 한 번: `npx -y @gessobuild/anti-slop check <폴더>/report.html --json` — 보고서 자체의 검출은 인용한 가격·표 밀도(참고 등급)만 남아야 한다.
