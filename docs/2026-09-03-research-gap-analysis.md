## 2. 추가 후보 (근거·자동화 가능성)

### 2-1. AI 답변 노출 제어 지시자 (근거 A · 자동화 가능)
구글 로봇 메타 문서가 AI Mode·AI Overviews 를 포함하도록 개정됐다. `nosnippet`·`max-snippet`·`data-nosnippet` 이 AI 답변의 **직접 입력**을 차단한다.

**실측(76페이지 전수):** 차단 지시자(`nosnippet`·`noarchive`·`max-snippet:0`·`data-nosnippet`)는 **0건**. 즉 지금 막고 있지는 않다. 다만 명시적 최대 허용(`max-snippet:-1`, `max-image-preview:large`)도 **76/76 페이지 미설정**.

→ 룰을 두 갈래로 나눠야 정직하다.
- **차단 감지(P1)**: `nosnippet`·`max-snippet:0`·핵심 본문을 감싼 `data-nosnippet` → 실제 결함
- **명시 허용 권고(참고)**: 미설정은 결함이 아니다. 구글이 알아서 판단한다. 다만 AI 표면 노출을 최대화하려면 한 줄 추가가 값싼 선택 → 참고 등급으로만

신규 룰 `S-T-snippet-block`(P1) · `S-T-snippet-optin`(참고).

### 2-2. GEO 논문 검증 기법의 페이지 신호화 (근거 A · 자동화 가능)
Aggarwal et al., KDD 2024(arXiv 2311.09735), GEO-bench 10,000 쿼리·25 도메인. 가시성 지표는 Position-Adjusted Word Count.

| 기법 | 가시성 향상 | 페이지에서 재는 법 |
|---|---|---|
| 인용문 추가 | **+41%** | 따옴표로 묶인 10자 이상 문장 수 / 본문 1,000자 |
| 통계 추가 | **+32%** | 숫자+단위 조합 밀도 (이미 스캔함, 1.7~7.1 편차 4배) |
| 출처 인용 | **+28%** | 외부 권위 도메인(.go.kr·.or.kr·.ac.kr·언론·위키) 링크 수 |
| 유창성 | +28% | (기계 판정 어려움 · 제외) |
| 전문 용어 | +18% | 업종 용어 사전 필요 · 보류 |
| 키워드 스터핑 | **−9%(해로움)** | 최빈 단어 반복률. 다만 한국어는 조사·상호 반복이 있어 오탐 위험 → 참고 등급 |

→ 신규 룰 `G-C-quote`, `G-C-stats`, `G-C-source`, `G-C-stuffing`(참고).

### 2-3. 최신성 세분화 (근거 B · 자동화 가능)
플랫폼별 신선도 창이 다르다. 30일 내 갱신 = 약 3.2배 인용, Perplexity ~30일 / ChatGPT ~90일 / Google AI Overviews 는 `dateModified` 스키마 의존.
현재 우리 기준은 180일 하나뿐이라 너무 느슨하다. → 30일/90일/180일 3구간으로.

### 2-4. 구조화 데이터 확장 — **GEO 근거는 반박됨, SEO 목적으로만** (근거 A · 자동화 가능)

**⚠ 초안 정정.** 처음에 "스키마 있으면 AI 인용 2.5배" 같은 업계 수치를 근거로 삼았는데, Ahrefs 가 매칭 이중차분(DiD) 인과실험으로 이를 반박했다. 처리군 1,885페이지(2025-08~2026-03 신규 스키마 추가) vs 대조군 4,000페이지(3:1 매칭, 처리 전 인용 수준 유사):

| 표면 | 스키마 추가 효과 |
|---|---|
| ChatGPT | +2.2% (영점과 통계적 구분 불가) |
| Google AI Mode | +2.4% (동일) |
| Google AI Overviews | **−4.6% (작지만 통계적으로 유의한 감소)** |

상관관계상 "AI 인용 페이지가 스키마 보유 확률 3배" 였던 것은 **스키마를 붙이는 사이트가 원래 더 정교하고 권위 있기 때문**(교란변수)이다. 직접 리트리벌 테스트에서 주요 AI 시스템은 숨은 마크업(JSON-LD·Microdata·RDFa)을 무시하고 **보이는 HTML 만 추출**했다.

→ 결론:
- `Organization`·`WebSite`+`SearchAction`·`Article` 은 **전통 검색·리치결과·엔티티 정합 목적으로만** 추가 권고한다. GEO 점수 가산 근거로 쓰지 않는다.
- 대신 **같은 사실을 화면에 보이게** 쓰는 것이 AI 인용에 직결된다. 특히 **날짜**: 숨은 `dateModified` 보다 본문에 눈에 보이는 발행·수정일 텍스트가 더 중요.
- **스키마 드리프트**(JSON-LD ↔ 화면 불일치)는 여전히 유효한 결함이다. 구글이 신뢰를 잃는 원인이고, 우리는 지금 FAQ 만 본다 → 가격·영업시간·전화로 확장.

### 2-5. hreflang 상호참조 검증 (근거 A · 자동화 가능 · **우리 사이트에는 결함 없음**)
지금은 존재 여부만 본다. 실제 실패 1위는 **return tag 부재**(A가 B를 가리키는데 B가 A를 안 가리킴)와 자기참조 누락, 상대 URL 사용이다. 클러스터가 깨지면 구글이 주석 전체를 무시한다.

**⚠ 자체 정정.** 프로토타입 1차 실행에서 사이트 A에 "자기참조 없음·return tag 없음 5건" 이 나왔으나, **내 검사 코드가 x-default 를 상호참조로 인정하지 않은 버그**였다. 언어 선택 루트(`/`)는 x-default 로만 자기를 가리키는 것이 표준이다. 수정 후 재검증:

| 사이트 | hreflang 페이지 | 자기참조·return·절대URL | 판정 |
|---|---|---|---|
| 사이트 A | 9 | 문제 0건 | 정상 |
| 사이트 B | 12 | 문제 0건 (선언됐지만 미수집 URL 4개는 결함 아님) | 정상 |

→ 룰 자체는 넣을 값어치가 있다(다른 사이트에서 흔한 실패). 다만 **우리 열 곳에서는 지금 결함이 없다**. 구현 시 x-default 를 반드시 유효 참조로 인정하고, 수집 안 한 URL 은 "미확인" 으로 분리해야 오탐이 안 난다.

### 2-6. 한국 법정 표기 · 신뢰 신호 (근거 A · 자동화 가능 · **0/10**)
- 개인정보처리방침: 개인정보를 수집(폼)하면 수립·공개 의무. 미공개 시 1천만원 이하 과태료. 열 곳 중 폼이 있는 곳은 사이트 H(/reservation) 1곳 → 그곳은 명백한 위험
- 사업자등록번호·통신판매업 신고번호: 통신판매업자 표시 의무(미신고 영업 최대 500만원)
- 이용약관·대표자명·주소·연락처: E-E-A-T 의 Trustworthiness 신호이기도 하다
→ 신규 룰 `S-T-legal`(폼 있으면 P1, 없으면 참고), `G-T-legal`. **업종·판매 형태에 따라 의무 여부가 다르므로 기본 HOLD, 폼 감지 시 승격.**

### 2-7. 접근성 (근거 B/C · 자동화 가능 · 실측 완료)
axe-core 4.13 을 Playwright 에 주입해 실제로 돌려 봤다.
- 사이트 H 색 대비 위반 **28건(serious)**, 사이트 D **7건**, 사이트 F·사이트 J 0건
- axe-core 는 WCAG 이슈의 약 57% 를 자동 검출(나머지는 사람 판단)
- 접근성은 직접 랭킹 요인이 아니지만 헤딩 순서·라벨·대비는 SEO·가독성과 겹친다. **사용자 CLAUDE.md §6 이 이미 "앰버 배경 위 앰버 글자 금지, 반투명 10% 텍스트 금지" 를 규정** → 우리 디자인 레인의 빈 구멍
→ 신규 단계 또는 `site_render.py` 안에 통합. 룰 `D-a11y-contrast`, `D-a11y-heading`, `D-a11y-label`.

### 2-8. INP 실측 (근거 A · **부분** 자동화 · 실측 완료)
2026 기준 CWV 는 LCP<2.5s · **INP<200ms** · CLS<0.1. 우리는 TBT(랩 대리지표)만 잰다.
프로토타입: 모바일 390px·CPU 4× 에서 클릭 가능한 요소 7개를 스크립트로 눌러 `PerformanceObserver('event')` 로 측정 → **사이트 J INP 80ms** 측정 성공.
한계: 실제 사용자 조작이 아니라 랩 값이다. "실사용자 INP 는 CrUX 로 봐야 한다" 고 명시해야 한다.

### 2-9. CrUX 실사용자 데이터 (근거 A · 조건부)
CrUX API 는 무료(150 qps)지만 **Google Cloud API 키 필요**. 트래픽이 적은 사이트는 데이터 없음. 열 곳 중 대부분이 소규모라 origin 단위로도 안 잡힐 가능성이 높다.
→ 키가 있으면 붙이고, 없으면 "확인하지 못한 것" 에 명시(현행 유지).

### 2-10. 엔티티 강화 (근거 B/C · 부분 자동화)
브랜드 웹 언급이 AI Overview 인용과 상관 0.664, 백링크는 0.218. Wikidata 항목·프로필 일관성이 지식그래프 진입 조건.

## 5. 학술 조사 보강 (arXiv 8편 + 1차 실측 11건 직접 확인)

### 5-1. 가장 강하게 재현된 요인 — 관련성 · 문맥 내 위치 · 질문 직결
Vishwakarma et al. 2026(arXiv:2605.25517): LLM 6종에 **252,000회 시험**, 두 경쟁 소스가 **정확히 한 요소만 다르게** 하는 요인설계. 최초 인용을 결정하는 최대 요인은 **관련성과 문맥 내 위치**였다. Aggarwal 2024·Puerto 2025·서베이(2607.14035) 모두 신뢰도 "High" 로 일치한다.
→ 우리 룰로: 헤딩 직후 첫 문단이 그 질문에 **짧고 직접** 답하는가(`G-C-answer-first`). 지금 `G-C-question`(질문형 소제목)만 있고 "답이 바로 오는가" 는 안 본다.

### 5-2. 고정 휴리스틱의 한계 — 반드시 보고서에 적을 것
Puerto et al. 2025 C-SEO Bench: 54개 (방법×도메인) 조합 중 **유의하게 긍정인 것은 3개뿐**, QA 태스크에서는 **0개**. 널리 채택될수록 제로섬이 된다.
Kim et al. 2026(SAGEO): 문서 171,003개·쿼리 2,700개. "AI 인용을 노린 본문 재작성" 은 상위-20 노출 −9%, 재순위 후 상위-10 −16%, **최종 인용 −6%**. 주입 후엔 잘 보이지만 검색 자체에서 덜 뽑힌다.
→ 스킬 원칙에 추가: **"AI 인용을 위해 본문을 다시 쓰라" 고 권하지 않는다.** 사실을 더하는 것(통계·인용·출처)과 문체를 바꾸는 것은 다르다.

### 5-3. 신뢰 신호 · 브랜드 언급 (상관)
- 리뷰 프로필 없음 1% → 강한 프로필(리뷰 80+·오너 응답) **75.3%** AI 인용률. Seer×Trustpilot, AI 응답 800,000건. 상관이지 인과 아님
- 브랜드 웹 언급 r=0.664(ChatGPT)~0.709(AI Mode), 백링크 r=0.218. Ahrefs 브랜드 75,000개 + Zyppy 54개 연구 메타분석에서 재확인
- URL 접근성(크롤러 미차단)이 23개 요인 중 최고점 9.5/10
→ 우리 `G-A-*`(크롤러 접근)·`G-T-review`·`G-T-profiles` 의 가중치를 지금보다 높게 볼 근거. 반대로 스키마 가중치는 낮춰야 한다.

### 5-4. 플랫폼별 차이 (진단 조언이 갈리는 지점)

### 5-5. 근거 없는 주장으로 확인돼 폐기한 것
- **"통계 데이터 포인트 19개 이상이면 인용 2~3배"** — 1차 논문에 그런 임계값 서술이 없다. GEO 논문의 PAWC 기준선(19.3~19.5)을 다른 지표와 뒤섞은 콘텐츠팜의 오독으로 보인다. **쓰지 않는다.** (내가 1차 조사에서 이 수치를 근거로 삼을 뻔했다)
- "스키마 있으면 AI 인용 3배" — 같은 팀의 인과실험이 반박(위 2-4)
- "AIO 인용의 38%만 top10" — Ahrefs 1차 데이터(76.10%, AIO 100만·인용 190만 분석)와 정면 배치. 검증 실패

### 5-6. llms.txt 최종 판정 (근거 보강)
Ahrefs 2026-06: 도메인 **137,210개** 검사, 28% 가 llms.txt 게시, **그중 97% 가 2026년 5월 한 달간 요청 0건.** Zyppy 메타분석에서 23개 요인 중 **최저점 2.0/10**.
→ 현재 P2 를 **참고(INFO)** 로 내리고, 보고서 문구를 "있으면 나쁘지 않으나 인용 지렛대가 아님(2026-06 기준 게시 도메인의 97% 가 한 달간 요청 0건)" 으로 바꾼다.

### 5-7. 스키마 드리프트 실측 (신규 룰 후보 검증 완료)
"JSON-LD 에 있는 값이 화면에도 보이는가" 를 열 사이트에서 쟀다. AI 는 숨은 마크업을 무시하고 보이는 HTML 을 읽으므로(2-4 근거), 스키마에만 있고 화면에 없는 사실은 **AI 에게는 없는 것**이다.

| 확인 | 결과 |
|---|---|
| **사이트 I** | 스키마에 요일별 영업시간(월 14:00~00:00 등)이 있는데 **홈 화면에 시각 표기가 0건**. 진짜 드리프트 |
| 사이트 A | 1차 스캔에서 "전화 화면에 없음" 이 나왔으나 **언어 선택 루트를 본 탓**. 대표 페이지 `/ko/` 기준 전화·영업시간 모두 화면에 있음 → 정상 (자체 정정) |
| 나머지 8곳 | 전화·영업시간 모두 화면에 보임. priceRange 는 대부분 기호(₩₩)라 대조 대상 아님 |

→ 신규 룰 `S-S-drift`: 업체 노드의 telephone·openingHoursSpecification·주소가 **대표 페이지 화면 텍스트에 나타나는지** 대조. 반드시 대표 페이지(언어 루트) 기준으로 볼 것.

## 6. 국내(네이버·카카오) 조사 — 공식 가이드 원문 기준

네이버 서치어드바이저 가이드는 라이브가 SPA·차단이라 Wayback 아카이브 원문을 직접 받아 확인했다(스냅샷 2020-09~2025-09).

### 6-1. 네이버 공식 기준 중 우리가 안 보는 것

| 항목 | 기준 | 우리 열 곳 실측 |
|---|---|---|
| **사이트맵·RSS 용량 10MB 이하** | 구글(50MB)보다 훨씬 엄격한 **네이버 고유 상한** | 0~5KB · 전부 여유 |
| 사이트맵 URL 50,000개/파일 | 초과 시 인덱스 분할 | 1~16개 |
| **robots.txt 가 JS/CSS·파비콘을 막으면 안 됨** | 막으면 네이버 로봇이 "주요 영역 해석" 실패 | 10/10 문제 없음 |
| **robots.txt Content-Type 이 text/plain** | HTML 로 주면 규칙이 무시될 수 있음 | 5곳 확인, 전부 `text/plain` |
| 해시뱅(`#!`)·프래그먼트로 콘텐츠 분기 | `#` 이후를 해석하지 않음 | 0건 |
| `<a href>` 아닌 JS onclick 링크 | 로봇이 URL 을 못 읽음 | 0건 |
| 모바일 별도 URL 시 상호 canonical/alternate | 누락 시 중복문서 | 해당 사이트 없음(전부 반응형) |
| IndexNow 키 파일 | 2023년부터 서치어드바이저 지원, 색인 보장은 아님 | 0/10 |
| 다음 웹마스터도구 PIN(robots.txt 최하단) | 메타가 아니라 robots 에 남기는 방식 | 0/10 (site-e 는 `User-Agent: Daumoa` 였고 PIN 아님 — 내 1차 스캔 오탐) |
| 한글 URL 유니코드 정규화(NFC) | macOS NFD 로 만든 slug 가 서버와 바이트가 달라 링크 깨짐 | 한글 URL 0건 |

→ 열 곳에서는 지금 걸리는 게 거의 없다. 그래도 **CMS·대형 사이트에서 흔한 실패**라 룰로 넣을 값어치는 있다. 특히 사이트맵 10MB 와 JS/CSS 차단.

### 6-2. 구조화 데이터 — 네이버 공식 필수 속성
- `PostalAddress`: `streetAddress` 필수
- `Restaurant`: `name` + `openingHours` 필수, 나머지 선택
- 사이트연관채널(`sameAs`): `name`·`url`·`sameAs` **3개 모두 필수**. 다만 마크업만으로 노출이 보장되지 않고 사이트명 고유성·신뢰도 조건이 따로 있다 → 보고서에 "마크업했다고 노출되는 것은 아니다" 를 명시해야 한다.

### 6-3. 카카오 (커뮤니티 확인 · 공식 문서 미확보)
- **카카오 디벨로퍼스에 도메인이 등록돼야 `Kakao.Share` 가 동작**. OG 태그가 완벽해도 콘솔에 도메인이 없으면 공유 자체가 실패한다. 매장 사이트에서 카카오톡 공유가 안 되는 흔한 원인
- 공유 이미지 최소 80×80px·500KB 이하, 권장 800×400(2:1)
→ 사이트에서 잴 수 있는 것은 "Kakao SDK 스크립트·appkey 존재" 와 "OG 이미지 규격" 까지. 콘솔 등록 여부는 판정 불가 → HOLD 로.

### 6-4. **용어 정정 필요 — "AiRS"**
조사 결과 **AiRS 가 네이버 플레이스 랭킹에 공식 적용되는 용어인지 확인되지 않았다.** "에어서치(AiRSEARCH)" 는 2021년 통합검색을 대체한 브랜드명이고(공식 보도자료 확인), AiRS 는 원래 뉴스·콘텐츠 추천 시스템 명칭에 가깝다.
→ 우리가 지금까지 보고서에 쓴 "AiRS 정렬로 N위" 표현을 **"네이버 플레이스 검색의 유기적(광고 제외) 노출 순서"** 로 바꿔야 한다. 측정값 자체(pcmap organic 순서)는 유효하다. `naverai` 스킬 문서도 같이 손봐야 한다.

### 6-5. 확인된 사실 vs 업계 추정 (보고서에서 구분할 것)
- **공식**: robots 문법·응답코드 처리, 사이트맵 10MB·5만 URL, URL 구조 권장, 모바일 3방식, 콘텐츠 스팸 판정 기준, 사이트 이전 절차, 구조화 데이터 필수 속성, IndexNow 지원, 신디케이션이 2018.6부터 제휴 전용, AI 브리핑 2025-03 도입·네이버 메이트(2026.6, 월 3,000명, 인용수 기반, 연 200억원)
- **비공개·업계 추정**: AI 브리핑 인용 알고리즘, C-Rank/D.I.A/D.I.A+ 세부 요소(1차 원문 미확보), 스마트플레이스 노출 랭킹 가중치

### 10-5. 인용의 두 단계 — 선택 vs 흡수
- **선택**(인용 후보에 드는가): 도메인 권위·언어권이 좌우 → 우리 범위 밖(브랜드 언급·외부 프로필)
- **흡수**(답변 문장을 실제로 지배하는가): **페이지 내부 구조가 좌우** → 우리 진단기의 영역
- 최강 단독 상관: LLM 평가 질의 적합성 r=0.43, 임베딩 유사도 r=0.36
- ChatGPT 프롬프트당 6.88개 인용·영향력 0.2713 vs Perplexity 16.35개·0.0646 (적게 인용하되 깊게 vs 많이 인용하되 얕게)
→ 보고서 문구에 반영: "우리가 사이트에서 고칠 수 있는 것은 **흡수**다. 선택은 사이트 밖(브랜드 언급·프로필·리뷰)에서 온다."

### 10-6. "1페이지 = 1질문"
인용의 최소 단위가 URL 이라는 구조적 사실. **고유 title 이 인용을 만드는 게 아니라, 1페이지 1질문 원칙을 지키면 고유 title 이 따라온다.** 우리 `S-O-title-dup`(제목 중복) 룰의 해석을 이렇게 바꿔 적는다.

Semrush·Ahrefs 대체재이고 실제 데이터는 **DataForSEO 유료 키**가 있어야 나온다. 키워드 리서치·순위 추적·백링크가 본체인데, 이 셋은 우리가 §9 3군(넣지 않는다)으로 분류한 것들이다. 로컬 SEO 스킬도 구글 비즈니스 프로필·맵스 전용이라 네이버 플레이스 시장에는 그대로 못 쓴다.

### 14-2. 철학은 거의 같다
"보고할 모든 항목을 실제 페이지 HTML 로 직접 확인하라. 증거를 보지 않은 것은 쓰지 마라" · "도구가 보고한 것과 내가 확인한 것을 구분해 적어라" · "백링크 데이터 없음은 감점이 아니라 기록 없음" · 줄표 금지 · 과장어 금지. 우리 규약과 독립적으로 같은 결론에 도달했다.

### 14-3. 오탐 1건을 알려줬다
그들의 `isDuplicateCandidate` 주석: *"운영자가 이미 noindex 하거나 canonical 로 정리한 페이지를 중복으로 잡으면, 이미 고친 것을 고치라고 말하는 셈"*. 우리 제목 중복은 canonical 은 이미 키로 묶어 처리하고 있었지만 **noindex 페이지는 걸러내지 않았다.** 수집 단계에서 제외하도록 고쳤다.

### 14-4. 반영한 룰 6개 (172개로)

| 룰 | 등급 | 열 곳 발화 |
|---|---|---|
| `S-C-dup-content` | P1 | 0/10 (본문 해시 비교. noindex·타 canonical 페이지 제외) |

`S-O-no-outlink` 는 처음 P2/weight 1 로 넣었더니 site-g 점수가 1점 내려갔다. 오탐은 아니지만(원본 HTML `<a href>` 0개 확인) 자바스크립트로 내비게이션을 그리는 사이트에서는 해석이 갈려서, 규율 #2 를 지켜 **참고 등급으로 내려 드리프트를 0 으로** 만들었다.

수집에 `probe_redirects` 추가 — 리다이렉트한 페이지만 골라 `follow=False` 로 홉을 하나씩 따라간다(최대 6홉, 20건). 순환도 같은 경로로 잡힌다.

### 14-5. 보고서 구조 변경 — "이번 주에 할 일 하나"

그들의 지적: *"Skip nitpicks that do not matter for the specific site. **A beginner report with twenty findings has failed.**"* 우리 보고서는 사이트당 조치 대상이 20~34건이다.
